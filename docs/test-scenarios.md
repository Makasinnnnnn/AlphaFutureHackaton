# Тестовые сценарии

## Автотесты

```bash
# нужен локальный PostgreSQL; тесты создают отдельную БД conveyor_test
cd backend && pip install -r requirements.lock.txt -r requirements-dev.lock.txt
pytest -q
```

41 тест:

| Файл | Что проверяет |
|---|---|
| `tests/test_domain.py` (26) | Скоринг (сумма факторов, стоп-факторы, границы), кредитное решение (одобрение, контрпредложение по выручке и по сроку, серая зона, альтернативный продукт, залог, овердрафт, один балл — разные решения по продуктам), аннуитет и график, state machine (допустимые и недопустимые переходы, терминальные статусы), полнота заявки, распознавание выписок (два формата, cp1251, ошибки) |
| `tests/test_api_flow.py` (15) | Сквозные сценарии через HTTP API и воркер на реальном PostgreSQL и симуляторе источников: все 7 персон, дозапрос с распознаванием выписки, решение аналитика, запрос данных аналитиком, конфликт версий, идемпотентность, RBAC, изоляция клиентов, типы файлов |

Сквозная проверка работающей системы (после `docker compose up`):

```bash
pip install httpx && python scripts/e2e_check.py --base http://localhost:8080
```

## Ручная проверка через интерфейс

Откройте http://localhost:8080. На странице входа — тестовые учётки, вход в один клик. Пароль у всех `demo2026`.

### Сценарий 1. Автоматическое одобрение и выдача — `anna@demo.ru`

1. Главная: реквизиты компании подтянуты из реестра, обороты по счёту показаны без ввода.
2. «Получить финансирование» → «Закупить товар или сырьё» → «Оборотный экспресс-кредит».
3. Сумма 2 000 000 ₽, срок 12 мес. → «Сохранить и продолжить».
4. Шаг «Данные о бизнесе»: обороты уже в заявке. «Продолжить» → согласие → «Отправить заявку».
5. **Ожидаемо:** маршрут заявки обновляется сам, через 6–10 с — «Кредит одобрен», 19% годовых.
6. «Принять и перейти к договору» → договор и график → галочка → «Подписать и получить деньги».
7. **Ожидаемо:** статус «Кредит выдан», полный график платежей, в колокольчике — уведомления.

### Сценарий 2. Контрпредложение — `start@demo.ru`

1. «Открыть новое направление» → «Оборотный экспресс-кредит», 5 000 000 ₽ на 24 мес.
2. **Ожидаемо:** «Банк предлагает другие условия»: 3 120 000 ₽ вместо 5 000 000 ₽, в причинах — «Сумма великовата относительно выручки бизнеса».
3. Дополнительно: заявка на «Кредит на оборудование» (бизнесу 10 мес. при минимуме 12) — после загрузки счёта банк предложит оборотный кредит вместо кредита на оборудование.

### Сценарий 3. Дозапрос и распознавание выписки — `kovalev@demo.ru`

1. «Купить оборудование или транспорт» → «Кредит на оборудование», 1 800 000 ₽ на 36 мес. Поля оборудования оставьте пустыми, документы не загружайте, отправьте заявку.
2. **Ожидаемо:** «Нужна дополнительная информация» — выписка, описание оборудования, счёт.
3. Укажите «Фрезерный станок с ЧПУ», 2 000 000 ₽ → «Сохранить». Загрузите `test-data/statement_kovalev_6m.csv` и `test-data/invoice_cnc_machine.pdf`.
4. **Ожидаемо:** выписка распознана — 6 месяцев, в среднем 900 000 ₽, появился график оборотов.
5. «Отправить повторно» → **ожидаемо:** «Кредит одобрен», 17% (ставка ниже за счёт залога).
6. Ошибка формата: загрузите любой CSV без колонок даты и суммы — понятное сообщение, что не так.

### Сценарий 4. Ручное рассмотрение — `sever@demo.ru` и `analyst@demo.ru`

1. Клиент: «Закрыть кассовый разрыв» → «Оборотный экспресс-кредит», 1 500 000 ₽ на 12 мес. → отправить.
2. **Ожидаемо:** «Рассматривает специалист».
3. Аналитик: очередь «Ждут решения» → заявка. Видно: балл 50 (C), вклад каждого фактора, рассчитанные лимиты, сработавшие правила, рекомендация конвейера; вкладки «Проверки» (ответы ЕГРЮЛ, ФНС, БКИ) и «Аудит».
4. Выберите «Контрпредложение», 1 200 000 ₽, обоснование → отправить.
5. Клиент: **ожидаемо** — предложение с комментарием специалиста в причинах.
6. Вариант: «Запросить данные» с пунктом «Приложите договоры с заказчиками» → у клиента статус «Нужна дополнительная информация» с этим пунктом.

### Сценарий 5. Отказ по стоп-фактору — `vector@demo.ru`

Любой продукт. **Ожидаемо:** «Отказ», в причинах — текущая просрочка более 30 дней и налоговая задолженность.

### Сценарий 6. Ликвидированная компания — `zakat@demo.ru`

На главной статус «Ликвидирована». Подайте заявку → **ожидаемо:** отказ сразу после проверки в реестре, шага «Оцениваем заявку» в маршруте нет.

### Сценарий 7. Недоступность внешнего источника — `tikhonova@demo.ru`

«Овердрафт», 300 000 ₽. **Ожидаемо:** заявка дольше обычного на «Проверяем компанию» (повторы), затем «Рассматривает специалист». У аналитика во вкладке «Аудит» — записи `INTEGRATION_RETRY`, в «Проверках» — ошибки БКИ `HTTP 503`, рекомендация проверить источник вручную.

### Сценарий 8. Отказоустойчивость при случайных сбоях

```bash
MOCK_FAILURE_RATE=0.3 docker compose up -d mocks
```
Подайте несколько заявок: часть запросов к источникам падает, но благодаря ретраям заявки доходят до решения, в логах воркера видны повторы.

### Сценарий 9. Масштабирование воркеров

```bash
docker compose up -d --scale worker=3
```
Заявки обрабатываются параллельно, без двойной обработки (`FOR UPDATE SKIP LOCKED`).

## Негативные проверки API

| Действие | Ожидаемо |
|---|---|
| Сумма вне лимитов продукта | `422 INVALID_PARAMS` с текстом лимитов |
| Подписать черновик | `409 INVALID_TRANSITION` |
| Изменить сумму на этапе дозапроса | `409 CONFLICT` |
| Решение аналитика с устаревшей `version` | `409 CONFLICT` |
| Отправить без согласия | `422 VALIDATION_ERROR` |
| Чужая заявка | `404` |
| Клиент открывает кабинет аналитика | `403` |
| Загрузка `.exe` | `415` |
| Повтор создания с тем же `Idempotency-Key` | та же заявка, без дубля |
